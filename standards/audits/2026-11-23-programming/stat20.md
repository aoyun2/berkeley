# STAT20 programming exercise audit

Read-only audit, 2026-11-23. Scope: both `exercises.html` and `exercises.zip` in `semesters/2026-fall/stat20/handouts/2026-11-16-causation-experiments/` (6 coding blocks) and `review-weeks-9-12/` (10 blocks). No exercise files modified.

## Assessment

The reference calculations generally work and the case studies connect code to statistical interpretation. The two delivery formats contain identical coding blocks and data. However, these are execution sandboxes with worked answers, not tested programming assessments. Two supplied narratives are contradicted or overstated by their actual computations, and causal interpretation needs correction. Repeated prose review alone would not have found these runtime issues.

## Findings

1. **High: permutation exercise yields an unexplained zero Monte Carlo p-value.** Causation HTML lines 198–221 (`w2b`), embedded solution at lines 306–309, and ZIP `solutions.R`, block `w2b`, use 1,000 permutations with seed 20 and `mean(abs(perm_ates) >= abs(obs_ate))`. Running the supplied reference yields **0** exceedances and prints **0**. This is a Monte Carlo estimate, not an exact zero null probability. Independently counting all fixed-size assignments by dynamic programming on the integer tenths of quiz scores gives **79,434 extreme assignments / choose(30,15)=155,117,520**, hence exact absolute-tail p **0.0005120891566600601**. The observed difference is 5.453333 points. Require the solution to identify Monte Carlo resolution/uncertainty and distinguish it from exact enumeration; a valid add-one Monte Carlo test uses `(b+1)/(B+1)` under its specified sampling protocol (here 1/1001), not a claim that this equals the exact tail. The exact-distribution conceptual answer in Question 2.2 is valid, but the implemented 1,000 random draws do not enumerate it.

2. **High: the overfitting narrative does not describe the supplied data.** Review HTML lines 255–258 says test RMSE “spikes” and wild polynomial wiggles fail to generalize. `solutions.R` block `c3b` and browser reference actually return additive **1.4551422**, interaction **0.9126910**, flexible polynomial **0.9531284**. The flexible model is slightly worse than interaction but substantially better than additive; this does not support the dramatic stated failure. Its design has rank 17 on 24 observations, training R² **0.9962731**, training RMSE **0.4145878**. The larger training/test discrepancy is useful evidence to discuss, but “low bias, very high variance” is not established by one split. Revise the question to ask what these actual numbers justify, or deliberately create and verify a fixture exhibiting the stated failure; do not predetermine a conclusion contradicted by output.

3. **High: no correctness tests in either format.** HTML `runEditor` (causation lines 394–453; review lines 572–631) captures execution and sets `exercise-status pass` with visible text **“ran”** when no error occurs. The visible wording is appropriately about execution, but there are no output/property checks. Neither ZIP contains any test file or assertions. Runtime counterexamples: setting `obs_ate <- 0` produces p=1 without an R error; changing bootstrap `replace=TRUE` to `FALSE` produces the degenerate interval `[38.51667,38.51667]` without an error. Both satisfy the current success branch. Reference execution should be accompanied by meaningful wrong-answer, invariant, and fixture tests, while keeping execution status distinct from correctness.

4. **High: covariate checks are described as verifying comparability of all traits.** Causation HTML line 159, Question 2.1 answer, says comparable-in-expectation across observed and unobserved traits is “verified on prior_gpa.” Randomization establishes the expectation statement by design; one observed GPA summary cannot verify it, especially for unobserved traits. Actual GPA means differ, 3.158 versus 3.353333, which is not itself evidence against randomization. The answer should separate design-based justification from a realized balance diagnostic.

5. **Medium: salary adjustment is given an unwarranted causal interpretation.** Causation HTML line 101, Question 1.2 answer, asserts department is a confounder and regression “isolates equal pay for equal department work.” The provided table establishes a composition difference and a conditional association, not the causal direction connecting group, department access, and pay; it also does not control job, tenure, or other determinants. Department could be a mediator for a total group-disparity question. The numerical adjusted coefficient +4.298734 is correct; its causal interpretation requires an explicitly stated causal model/assumptions.

6. **Medium: the downloadable exercises omit the reasoning tasks and reference results.** Both ZIP `README.md` files tell students to use `exercises.html` in a browser, but neither archive includes that file or a URL. Archives contain only data, starter R, solution R, and the two-line README. All conceptual questions, interpretation prompts, case-study context, and expected-output displays live solely on the web page. Thus the coding text is synchronized, but the pedagogical experience is not equivalent. Include/link the full prompts and explain prerequisites/dependencies and how to run a section. `library(tidyverse)` is required locally; the browser instead supplies a small custom verb implementation.

7. **Medium: little independent evidence of method selection or transfer.** Review `exercises.R` blocks `c3a` and `c5a` are already complete executable solutions; their browser starters equal their solutions. Causation `w3a` runs a means table unchanged but leaves the DID as a comment with no checked required result. Most other tasks fill a formula/function blank after the method and expected results are given. This is useful guided practice, but cannot establish independent competence. Add a small separate task requiring a method choice, result interpretation, and a check on unfamiliar data; do not characterize successful execution of these starters as mastery.

## Verified strengths and numerical results

- All **16 reference solutions** executed sequentially without reported R errors in WebR, using each page's actual custom prelude. Regression, interaction, bootstrap, logistic, and DID code produced coherent results.
- Salary pooled gap −31.31061 and adjusted +4.298734 reproduce the Simpson reversal; DID **0.5775** matches the regression interaction.
- Ice-cream test RMSE **1.87777**; driving linear/quadratic RMSE **8.0316094 / 0.9946058**; bootstrap Adelie interval **[37.05792,39.81708]** with supplied seed; logistic MCR/precision/recall **0.275 / 0.7272727 / 0.7619048**.
- Browser and ZIP starter/solution blocks match exactly after stripping surrounding whitespace: **6+10 blocks**. All **11 embedded datasets** match their CSV counterparts row-by-row and value-by-value: salaries40, notes30, gym80, icecream12, new_icecream4, driving18, new_driving6, cars_train24, cars_test12, penguins36, resumes40.
- Prescribed incomplete starters produce parse errors at `___`; 13 starters fail and 3 run (`w3a`, `c3a`, `c5a`). This is an execution diagnostic, not a semantic test suite. The wholly filled review starters are accurately identified above.
- Bootstrap replacement/sample-size reasoning, mean-versus-individual interval distinction, interaction interpretation, parallel-trends answer, and explicit state persistence are useful teaching choices.

## Validation and limits

Temporary artifacts and harnesses were kept outside the repository in the audit workspace’s `stat20-audit/` directory: `run.mjs`, `run-results.json`, `extra.mjs`, `extra-results.json`, extracted archive members, decoded preludes, and editor JSON. Execution outputs are preserved alongside this report as `stat20-run-results.json` and `stat20-extra-results.json`. Commands run in the temporary workspace: `npm install --prefix <temporary-audit-directory> webr --no-audit --no-fund`, `node run.mjs`, and `node extra.mjs`. Runtime reports **R 4.6.0 (2026-04-24)**. Native R/Rscript was not available. To run WebR under Node on Windows, only the temporary dependency's worker loader was changed to convert an absolute Windows path to a file URL; no R code/solutions/data were altered. Temporary decoded prelude CRLF was normalized to LF to match the HTML JavaScript string.

Exact permutation check used integer score tenths, a subset-sum dynamic program indexed by selected-count (15) and score sum, and the absolute-tail criterion `abs(2*sum_selected - sum_all) >= abs(2*sum_observed - sum_all)`. This counts every balanced assignment, including ties, without Monte Carlo error.

This is **runtime/statistical/source validation, not browser UI testing**. No browser interactions, CDN failure cases, keyboard behavior, or persistence behavior were exercised. The local tidyverse ZIP execution path was not run under native R; its code/data equality to the executed browser path was verified, but custom browser verbs are not claimed fully equivalent to dplyr. Headless npm WebR and the pages' unpinned `/latest/` CDN may differ; pinning versions and actual browser smoke tests remain necessary. No claims of dataset provenance were verified; archives do not supply source or simulation metadata. No exercise implementation fixes were made during this audit.
