Piece-by-Piece Breakdown: How SQLite Evaluates a Query

Before solving E1–E8, trace how every clause in a grouped SQL query transforms rows and groups from top to bottom (matching the logical execution stages: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT).

SELECT   b.author, COUNT(*) AS loan_count, SUM(l.days) AS total_days

FROM     books AS b JOIN loans AS l ON b.title = l.title

WHERE    b.pages >= 250

GROUP BY b.author

HAVING   COUNT(*) >= 2

ORDER BY total_days DESC, b.author ASC;
SQL pieceInput → OutputExact role and key rule
FROM books AS b JOIN loans AS l ON b.title = l.title7 × 7 = 49 raw pairs → matched rowsStage 1: Pairs rows across both tables where titles match. Qualify any shared column name (b.title) using table aliases.
FROM books AS a, books AS b WHERE a.title < b.titlen2 pairs → unique unordered pairsSelf-join pattern: a.title < b.title prevents self-matches and avoids listing (X, Y) and (Y, X) twice.
WHERE b.pages >= 250Matched rows → qualifying rowsStage 2: Filters individual rows before grouping. Aggregate functions (COUNT, SUM, MAX) are illegal here.
GROUP BY b.authorFiltered rows → 1 bucket per authorStage 3: Splits surviving rows into buckets sharing the same grouping key(s).
HAVING COUNT(*) >= 2All buckets → surviving bucketsStage 4: Filters whole groups using aggregates computed inside each bucket.
SELECT b.author, ... AS total_days1 row per bucket → named output columnsStage 5: Evaluates aggregates per group and binds column aliases (AS). Never mix ungrouped columns with SUM/COUNT.
ORDER BY total_days DESC, b.author ASCOutput rows → sorted rowsStage 6: Sorts final rows (ties in total_days break alphabetically by b.author).

Submission and checks

Use one SELECT (or WITH query) per editor, optionally preceded by CREATE TABLE eN AS. Do not modify source tables. Downloads use the same format as the offline checker. Every exercise runs independently on three datasets: the displayed example, boundary/tie/repeated-member cases, and empty tables. Passing means these checks passed, not a proof for every database.

Output columns, in order: E1 title; E2 author, n, total; E3 member, title, author; E4 first, second; E5 member, total; E6 author; E7 decade, n; E8 title. Row order matters for E1, E2, E5, E7 and E8; E3, E4 and E6 may use any row order. Preserve duplicate rows unless the task asks otherwise. For E5 return one alphabetically first member when totals tie; return no rows for empty loans.

E1

Titles of books with more than 260 pages, longest first; break equal-page ties by title.

Solution 
create table e1 as

  select title from books where pages > 260 order by pages desc, title;

E2

Each author with number of books and total pages (authors with at least two books), by author.

Solution 
create table e2 as

  select author, count(*) as n, sum(pages) as total from books

    group by author having count(*) >= 2 order by author;

E3

For each loan: member, title, author.

Solution 
create table e3 as

  select member, l.title, author from loans as l join books as b on l.title = b.title;

E4

Pairs of different books by the same author, each pair once.

Solution 
create table e4 as

  select a.title as first, b.title as second from books as a, books as b

    where a.author = b.author and a.title < b.title;

E5

The member with the most total loan days, and the total; break ties alphabetically by member.

Solution 
create table e5 as

  select member, sum(days) as total from loans group by member order by total desc, member limit 1;

E6

Authors whose books were borrowed by at least two different members.

Solution 
create table e6 as

  select author from books as b join loans as l on b.title = l.title

    group by author having count(distinct member) >= 2;

E7

Decade of each book with the number of books from it, oldest first.

Solution 
create table e7 as

  select year/10*10 as decade, count(*) as n from books group by decade order by decade;

E8 — independent transfer

Return titles of books that have never been borrowed, alphabetically. Build this query without copying E3. It must still work if a loan has a NULL title. Columns: title.

Solution — after an independent attempt
create table e8 as

  select b.title from books as b where not exists (select 1 from loans as l where l.title = b.title) order by b.title;
