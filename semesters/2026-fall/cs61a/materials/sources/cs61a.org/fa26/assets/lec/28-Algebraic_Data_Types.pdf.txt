Gleam Lists are Linked Lists

A list literal looks like a Python list: [3, 7, 5, 9]

However, a list literal can also contain an expression for the rest of the list

let s = [5, 7, 9]   This .. can only appear once, only at the end, and only before a list
let odds = [1, 3, ..s]   // Evaluates to [1, 3, 5, 7, 9], sharing memory with s

All items in a Gleam list must have the same type; the following cause type mismatch errors

[1, "two"]
["one", ..s]
[1, 3, s]

A list type describes the type of the items that the list contains
                    The list module contains map, filter, all, any, append, zip, etc.
import gleam/list
fn double_each(s: List(Int)) -> List(Int) {
  list.map(s, fn(n) { 2 * n })
}                                                A list of integers

List Patterns

There is no .first or .rest of a Gleam list

Instead, a case expression for a list can assign names to the first item(s) and the rest

fn describe(s: List(Int)) -> String {
    case s {
           [] -> "Empty list"
           [1] -> "List of just 1"
                                                                                                                                                                                        a is now a name for the first item in s
           [4, ..] -> "List starting with 4"
           [a, b] if a < b -> "List of " <> int.to_string(a) <> " then " <> int.to_string(b)
           [_, _] -> "List of two elements"
           [a, b, ..rest] if a < b -> "List ending in " <> string.inspect(rest)
           _ -> "Some other list"
    }                                                                                                               rest is now a name for the rest of the list
                                                                                                                        after the first two items (a and b)
}

 pub fn nth_equals(expected: a, s: List(a), n: Int) -> Bool {
   case s {
     [] -> True
     [first, ..rest] ->
            case n {
              0 -> first == expected
              _ -> nth_equals(expected, rest, n - 1)
            }
   }
 }

A case pattern gives local names to the fields (also "attributes") of each variant

 pub type Contact {                        contact(User("Oski", EmailOnly("oski@berkeley.edu")))
   EmailOnly(email: String)
   PhoneOnly(phone: Int)                    "mailto:oski@berkeley.edu"
   Both(email: String, phone: Int)
 }

 pub type User {
   User(name: String, contact: Contact)
 }

 pub fn contact(user: User) -> String {
     case user.contact {
         EmailOnly(e) | Both(e, _) -> "mailto:" <> e
         PhoneOnly(n) -> "tel:" <> int.to_string(n)
     }

Non-Empty Lists

Try to spot the bug in this implementation of increasing for non-empty linked lists

 pub type NotEmpty(a) {
   Last(first: a)
   Link(first: a, rest: NotEmpty(a))
 }

 pub fn starts_with(s: NotEmpty(a), v: a) -> Bool {
   s.first == v
 }

 pub fn increasing(s: NotEmpty(Int)) -> Bool {
   case s {
     Last(_) -> True
     Link(first, Link(second, _)) if second <= first -> False
     Link(_, rest) -> increasing(rest)
   }
 }
